## 2. 零训练诊断（下一步优先）

对Zone核心处理/对照分别检查：训练各公式接受奖励频率与长度分布、动作幅度和区域覆盖、命题访问/自动机q变化、epsilon决策比例、终止原因，记录真实轨迹而非从SR猜原因。比较早/中/晚更新，防止末条日志掩盖崩溃或未探索。

记录HV两头目标/输出/梯度尺度和gate分布；比较价值融合与单critic的优势尺度。Options记录候选数、选择分布、duration、命中/超时及内外在回报；零meta梯度只有结合单候选比例才能解释。

对同一冻结checkpoint分别做确定性和采样评估，预先固定seed与回合，并完整展示两种模式。不能看结果后切换主指标或删除失败模型。

验收：先定位具体数据异常或明确排除假说；没有证据时保留“不明原因”。不因单条loss有限而宣称正常学习。

## 3. 单目标控制检查

在Zone固定F blue/F green，采用同环境、奖励、编码器、actor/预算的gnn_single与hv_only最小配对。先低预算一个种子筛查，观察访问率与接受回报曲线；单目标不学习时先查控制/奖励，不直接扩大多任务训练。

任何修复都记录修改前后、协议hash、任务集与预算；重跑短时协议测试，新增新批次。不得修改已有结果文件或用新实现静默载入旧模型。

## 4. 小规模确认

按诊断只改变一个主要因素，用独立validation选择方案；保留全部探索尝试。锁定后在Zone至少3独立训练seed，以新重置测试集合确认，报告SR、违反、折扣回报与接受访问。主张需考虑不确定性及查看旧测试集的适应性风险。

验收：主要任务远离地板、配对方向稳定、违反率无不可接受恶化；收益不足时收缩主张或报告负结果，不强行筛选正向配置。预算仅小幅阶梯增长，提交下轮计划后再启动长训。
